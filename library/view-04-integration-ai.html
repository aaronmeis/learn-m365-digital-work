Identity and access

  • Identity provider: Microsoft Entra ID — OAuth 2.0/OIDC and SAML SSO for federated user identity; SCIM for joiner-mover-leaver lifecycle automation.
  • Delegated (user-context) authorization preferred for user-requested retrieval where entitlement is evaluated dynamically; managed application/workload identities, certificates, and short-lived tokens preferred for service-to-service workloads.
  • Least-privilege scopes: read/search permissions kept separate from write/action permissions.
  • Distinct application registrations and credentials maintained across dev/test/staging/prod; no generic shared accounts or long-lived static tokens.
  • GitHub side: GitHub Apps (installation-scoped, short-lived tokens) are the default for server-to-server integration; OAuth apps for user-delegated third-party access; PATs avoided for durable enterprise service integration.
  • MCP servers treated as production integration endpoints — centrally cataloged (owner, purpose, data classification, action permissions, auth method, lifecycle state, approval date); read-only tools separated from write-capable tools; consequential actions (create/modify/delete/deploy/approve/transmit) require user confirmation or workflow approval, bound to verified identity rather than natural-language request alone.

Integration risks

Risk Where Mitigation Source
Oversharing / permission mismatch Synced connector ACL translation from source system to M365 Map source-system entitlements precisely into connector ACLs; classify data before indexing; audit ACL fidelity before go-live mind-map: "permission fidelity" is non-negotiable, learn.microsoft.com/microsoft-365/copilot/connectors/overview
Stale or duplicated regulated data Synced connector indexing dynamic/sensitive records that should stay authoritative in source Use federated MCP connector instead of syncing for highly dynamic, sensitive, or too-large-to-duplicate data learn.microsoft.com/microsoft-365/copilot/connectors/federated-connectors-overview
Prompt injection via retrieved content Any AI feature grounding on external/synced/federated content Separate retrieved content from system instructions; validate parameters; allowlist tools; enforce action policy outside the model mind-map: Agent and MCP controls
Unauthorized consequential action via MCP tool MCP servers with write/action capability (ticket creation, deploy, delete) Separate read-only vs. write-capable tools; require user confirmation/workflow approval for consequential actions; bind to verified identity, not NL request alone mind-map: Agent and MCP controls
Ungoverned/point-to-point AI connections Ad hoc connector or MCP integrations built outside a central catalog Central MCP/API catalog with owner, purpose, classification, auth method, lifecycle state; Copilot Integration Enablement Layer (gateway/catalog/policy/audit) mind-map: Recommended target state
Deletion/legal-hold propagation gaps Synced content in Graph index/cache after source deletion or legal hold Ensure deletions, permission changes, and legal holds propagate to indexes, caches, downstream stores, and AI retrieval layers mind-map: Data and content controls
Broad OAuth scope on GitHub integration Third-party GitHub integration using OAuth app instead of GitHub App Default to GitHub App (fine-grained repo/org permissions, short-lived installation tokens) for server-to-server integration; reserve OAuth for genuine user-delegated cases mind-map: GitHub App versus OAuth app
LLM coordinating lifecycle state directly Using Copilot/agent as the system of record for PR/change lifecycle transitions Keep API/event integrations (webhooks, Checks API, branch protection) as system of record; Copilot explains/accelerates but does not own state transitions mind-map: Event-driven GitHub pattern

Terms on this page

Full list: GLOSSARY.

Term Definition
Permission fidelity Source permissions must be mapped onto Graph ACLs. A bad map becomes oversharing once Copilot retrieves the item.
Prompt injection Instructions hidden in retrieved content. Do not let that text authorize a tool call.
GitHub App Preferred server-to-server GitHub identity: scoped permissions, short-lived tokens.
OAuth app (GitHub) User-delegated GitHub access. Easy to over-scope; not the default for service integrations.
MCP server Endpoint that exposes tools. Catalog it and separate read tools from write tools.
Copilot Studio Low-code agent host on the Microsoft 365 side.
GitHub Copilot Coding assistant. Separate license and product from Microsoft 365 Copilot.
