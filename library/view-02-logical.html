Logical View — Microsoft's Digital-Work Platform

Logical view of Microsoft's Digital-Work Platform: components, data entities, and flows, still vendor-neutral.

Pack: 00 - Microsoft's Digital-Work Platform Hub · Block: Block 3 · Prev: Conceptual · Next: Physical

Altitude rule

Logical means which parts and how they talk, independent of where they run. Components have responsibilities and interfaces. Data entities have attributes and relationships. Still no regions, SKUs, or hostnames.

Design decisions at this level

  • Prefer synced for durable, broadly-discoverable knowledge where search quality matters more than instantaneous freshness; prefer federated (MCP) for highly dynamic, sensitive, or too-large-to-duplicate data, or where the use case needs a governed write/update/delete action. Source: mind-map, "The architectural decision is often simple."
  • Copilot is explicitly not the integration layer — it is a user-facing orchestration layer sitting above durable integration assets (APIs, event streams, identity relationships, connectors, schemas, policy controls). This shapes where logic should live: in the gateway/catalog/policy layer, not in agent prompts. Source: mind-map, "key architectural correction."
  • Lifecycle state transitions (PR merge, deployment gates) stay owned by API/event integrations (Checks API, branch protection), not by an LLM coordinating state independently — "more reliable and auditable." Source: mind-map, "Event-driven GitHub pattern."
