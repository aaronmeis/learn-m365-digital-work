Block 5: Integration and AI elements

Block 5 of the Microsoft's Digital-Work Platform deep dive - integration and ai elements.

Time: 60 minutes · Goal: Third-party and external systems, APIs, identity, and the AI features and their data paths

Work in: Integration and AI Elements

Focus from mind map

  • Use synced/indexed content when discovery, search quality, and repeated knowledge retrieval matter more than instantaneous freshness.
  • Use federated/MCP access when data is highly dynamic, sensitive, too large to duplicate, or must remain in its authoritative source.
  • Use API/workflow actions when the integration changes state.
  • Metadata, such as title, URL, content type, author, timestamps, tags, and business identifiers
  • Semantic labels that improve retrieval and Copilot understanding
  • The authoritative system must retain control.
  • Use a Microsoft or partner prebuilt connector when it meets security, coverage, permission, lifecycle, and support requirements.
  • Build a custom synced connector when the source is proprietary, permission semantics are specialized, or domain metadata must be represented precisely.
  • Build a federated MCP connector when real-time data, external-system authority, and controlled actions are the priorities.
  • Use Copilot Studio for low-code agent experiences and Power Platform-native workflow orchestration.
  • An operator asks Copilot to find approved deployment and rollback procedures.
  • A solution architect searches across SharePoint standards and GitHub API documentation.
