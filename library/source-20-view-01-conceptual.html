Conceptual View — Microsoft's Digital-Work Platform

Pack: 00 - Microsoft's Digital-Work Platform Hub · Block: Block 2 · Next: Logical view

Altitude rule

Conceptual means what and why, not how. Name capabilities and actors. Do not name products, SKUs, services, or regions here. If a sentence needs a product name, it belongs in the physical view.

Problem and purpose

  • Enterprises run two distinct platforms that must interoperate without becoming one undifferentiated blob: a digital-work platform (communication, documents, collaboration, business process) and a software-delivery platform (source code, review, build, release). Each needs its own AI orchestration layer, but third parties, data, and identity must cross the boundary safely.
  • The problem this deep dive frames is: how does a governed enterprise let AI (Copilot on either side) act as a consumer and orchestrator of existing integration, authorization, and control architecture — rather than becoming an ungoverned bypass around it.
  • If absent: point-to-point AI connections proliferate, permission fidelity breaks (oversharing), duplicate systems of record emerge, and there is no auditable evidence trail for AI-initiated actions. Source: mind-map intake, "Recommended target state."

Actors

Actor Role Goal Trust level
End user (knowledge worker) Asks Copilot questions, requests actions via chat Fast, grounded answers and safe automation of routine tasks Delegated, user-context authorization
Developer Uses GitHub Copilot in IDE/CLI/Chat, reviews AI-proposed PRs Faster, higher-quality code changes with human-in-the-loop review Delegated, developer identity + branch protection
AI administrator Registers Copilot connectors/apps, grants Graph permission consent Controlled extensibility surface, auditable connector catalog Elevated (admin consent), scoped to registration
Platform/integration architect Designs the Copilot Integration Enablement Layer, MCP/API gateway, catalog Governed, reusable integration surface instead of point-to-point sprawl Design authority, not runtime access
Third-party system of record (ITSM, CRM, observability, GitHub) Source or sink of data reached via connector, API, or MCP Retain authority over its own data; expose only what's approved Least-privilege, scoped credentials
Security/compliance (SIEM/SOAR, Purview, auditors) Monitors, classifies, and audits data and AI actions across both platforms Full evidence trail, policy enforcement, incident detection Read-only + policy-enforcement, not user-facing
MCP server operator Builds/maintains an MCP server exposing tools to Copilot Reliable, scoped, auditable tool access for AI agents Production-endpoint trust level, cataloged

Key concepts (conceptual data)

Open questions

Mark silence; verify in Block 6 hands-on or via Microsoft Learn / GitHub Docs.
  • The mind map does not name a specific human role/title that owns the "Copilot Integration Enablement Layer" — treat as an architectural target state, not an observed organizational structure.
